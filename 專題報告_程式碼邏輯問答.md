## 一、雷達圖比例計算相關問題

### Q1: 雷達圖中的技能分數是怎麼計算出來的？

**答案：**
技能分數採用加權計算方式，由三個部分組成：

```499:512:api/student/skill-analysis.php
    // 計算最終分數 (0-100)
    foreach ($skillScores as $category => &$data) {
        if ($data['portfolio_count'] === 0) {
            $data['score'] = 0;
            continue;
        }
        
        // 分數計算公式：
        // 作品數量權重 (40%) + 互動分數權重 (30%) + 完整度權重 (30%)
        $portfolioWeight = ($data['portfolio_count'] / $totalPortfolios) * 40;
        $interactionWeight = ($data['interaction_score'] / $data['portfolio_count']) * 30;
        $completenessWeight = ($data['completeness_score'] / $data['portfolio_count']) * 30;
        
        $data['score'] = min(100, round($portfolioWeight + $interactionWeight + $completenessWeight));
    }
```

**計算公式：**
- **作品數量權重** = (該技能類別的作品數 / 總作品數) × 40
- **互動分數權重** = (該技能類別的總互動分數 / 該技能類別的作品數) × 30
- **完整度權重** = (該技能類別的總完整度分數 / 該技能類別的作品數) × 30
- **最終分數** = min(100, 作品數量權重 + 互動分數權重 + 完整度權重)

**設計理念：**
- 40% 權重給作品數量，反映學生在該技能領域的投入程度
- 30% 權重給互動分數，反映作品的受歡迎程度
- 30% 權重給完整度，反映作品的品質和完整性

### Q2: 互動分數是怎麼計算的？為什麼這樣設計？

**答案：**
互動分數根據作品的瀏覽數、讚數和評論數計算：

```520:527:api/student/skill-analysis.php
function calculateInteractionScore($portfolio) {
    $views = $portfolio['view_count'] ?? 0;
    $likes = $portfolio['like_count'] ?? 0;
    $comments = $portfolio['comment_count'] ?? 0;
    
    // 互動分數計算：瀏覽數*0.1 + 讚數*2 + 評論數*3
    return min(100, ($views * 0.1) + ($likes * 2) + ($comments * 3));
}
```

**計算公式：**
互動分數 = min(100, 瀏覽數 × 0.1 + 讚數 × 2 + 評論數 × 3)

**設計理由：**
1. **瀏覽數權重較低 (0.1)**：因為瀏覽數容易被刷高，且互動性較弱
2. **讚數權重中等 (2)**：表示用戶對作品的認可，有一定價值
3. **評論數權重最高 (3)**：評論需要更多時間和思考，代表更深度的互動
4. **上限 100 分**：避免單一作品的分數過高，保持公平性

### Q3: 完整度分數是怎麼計算的？每個項目的權重如何決定？

**答案：**
完整度分數根據作品資訊的完整程度計算：

```532:557:api/student/skill-analysis.php
function calculateCompletenessScore($portfolio) {
    $score = 0;
    
    // 有標題 +10
    if (!empty($portfolio['title'])) $score += 10;
    
    // 有描述 +20
    if (!empty($portfolio['description'])) $score += 20;
    
    // 有內容 +20
    if (!empty($portfolio['content'])) $score += 20;
    
    // 有標籤 +15
    if (!empty($portfolio['tags'])) $score += 15;
    
    // 有封面圖片 +15
    if (!empty($portfolio['cover_image'])) $score += 15;
    
    // 有分類 +10
    if (!empty($portfolio['category_id'])) $score += 10;
    
    // 已發布 +10
    if ($portfolio['status'] === 'published') $score += 10;
    
    return min(100, $score);
}
```

**權重分配：**
- 標題：10 分（基本資訊）
- 描述：20 分（重要資訊，幫助理解作品）
- 內容：20 分（核心資訊，展示作品詳情）
- 標籤：15 分（便於分類和搜尋）
- 封面圖片：15 分（視覺吸引力）
- 分類：10 分（組織結構）
- 已發布：10 分（完成度指標）

**總分上限：100 分**

**設計理念：**
- 描述和內容權重最高，因為它們最能體現作品的品質
- 視覺元素（封面圖片）和組織元素（標籤、分類）也有一定權重
- 鼓勵學生完整填寫作品資訊，提高作品品質

### Q4: 技能匹配的邏輯是什麼？如何判斷一個作品屬於哪個技能類別？

**答案：**
技能匹配採用關鍵字匹配機制：

```461:495:api/student/skill-analysis.php
        // 檢查每個技能類別
        foreach ($skillCategories as $category => $keywords) {
            $matchScore = 0;
            $matchedKeywords = [];
            
            // 檢查標籤匹配
            foreach ($tags as $tag) {
                foreach ($keywords as $keyword) {
                    if (stripos($tag, $keyword) !== false) {
                        $matchScore += 2; // 標籤匹配權重較高
                        $matchedKeywords[] = $keyword;
                    }
                }
            }
            
            // 檢查標題和描述匹配
            $textContent = $title . ' ' . $description . ' ' . $content;
            foreach ($keywords as $keyword) {
                if (stripos($textContent, strtolower($keyword)) !== false) {
                    $matchScore += 1;
                    if (!in_array($keyword, $matchedKeywords)) {
                        $matchedKeywords[] = $keyword;
                    }
                }
            }
            
            if ($matchScore > 0) {
                $skillScores[$category]['portfolio_count']++;
                $skillScores[$category]['interaction_score'] += $interactionScore;
                $skillScores[$category]['completeness_score'] += $completenessScore;
                $skillScores[$category]['keywords_matched'] = array_unique(
                    array_merge($skillScores[$category]['keywords_matched'], $matchedKeywords)
                );
            }
        }
```

**匹配邏輯：**
1. **標籤匹配**：權重為 2（因為標籤是學生主動標記的，準確性較高）
2. **文字內容匹配**：權重為 1（在標題、描述、內容中搜尋關鍵字）
3. **不區分大小寫**：使用 `stripos()` 進行大小寫不敏感的匹配

### Q5: 為什麼雷達圖的分數範圍是 0-100？如何確保分數的公平性？

**答案：**

**分數範圍設計：**
1. **0-100 分制**：符合常見的評分習慣，易於理解
2. **使用 `min(100, ...)` 限制上限**：防止分數超過 100

```511:511:api/student/skill-analysis.php
        $data['score'] = min(100, round($portfolioWeight + $interactionWeight + $completenessWeight));
```

**公平性保證：**
1. **相對比例計算**：作品數量權重使用相對比例 `(作品數/總作品數)`，而非絕對數量
   - 例如：有 10 個作品，其中 3 個是前端開發，前端開發的作品數量權重 = (3/10) × 40 = 12 分
   - 這樣設計確保不同作品數量的學生可以公平比較

2. **平均化處理**：互動分數和完整度分數都除以作品數量，得到平均值
   - 互動分數權重 = (總互動分數 / 作品數) × 30
   - 完整度權重 = (總完整度分數 / 作品數) × 30
   - 避免作品數量多的學生在這些項目上佔優勢

3. **多維度評估**：結合數量、互動、完整度三個維度，避免單一指標偏差

### Q8: 作品對比功能中的雷達圖是如何計算不同學生的技能分數？

**答案：**
在作品對比功能中，使用不同的計算邏輯：

```830:870:frontend/js/portfolio-comparison.js
    getSkillScore(portfolio, skill) {
        // 根據作品分類和技能標籤計算技能分數
        let score = 0;
        
        // 基礎分數：根據作品分類
        const categoryName = portfolio.category_name || portfolio.category;
        if (categoryName === skill) {
            score += 70;
        }
        
        // 技能標籤匹配
        if (portfolio.skills && Array.isArray(portfolio.skills)) {
            const skillKeywords = this.getSkillKeywords(skill);
            const matchedSkills = portfolio.skills.filter(s => 
                skillKeywords.some(keyword => s.toLowerCase().includes(keyword.toLowerCase()))
            );
            score += matchedSkills.length * 20;
        }
        
        // 直接技能名稱匹配
        if (portfolio.skills && Array.isArray(portfolio.skills)) {
            const directMatch = portfolio.skills.some(s => 
                s.toLowerCase() === skill.toLowerCase() || 
                s.toLowerCase().includes(skill.toLowerCase())
            );
            if (directMatch) {
                score += 50;
            }
        }
        
        // 根據作品統計數據調整分數
        const engagement = (portfolio.views || 0) + (portfolio.likes || 0) * 2 + (portfolio.comments || 0) * 3;
        score += Math.min(engagement / 50, 30);
        
        // 如果沒有任何匹配，給予基礎分數

            score = Math.floor(Math.random() * 30) + 10; // 10-40分
```

3. **直接匹配**：如果技能名稱直接匹配，+50 分
4. **互動加成**：根據互動數據調整，最多 +30 分
5. **隨機基礎分數**：如果完全沒有匹配，給予 10-40 的隨機分數（這是為了演示目的）

**注意：** 這個計算方式與後端的 `analyzeStudentSkills` 不同，因為對比功能是基於單個作品，而不是所有作品的綜合分析。

## 四、性能與優化相關問題

### Q11: 如果學生有很多作品（例如 100 個），系統性能會如何？有優化措施嗎？

**答案：**

**潛在性能問題：**
1. **資料庫查詢**：目前使用 `ORDER BY p.published_at DESC`，如果作品很多，查詢可能較慢
2. **技能分析循環**：需要遍歷所有作品和所有技能類別，時間複雜度為 O(作品數 × 技能類別數)

**現有優化：**
1. **只查詢已發布的作品**：`WHERE p.user_id = ? AND p.status = 'published'`
2. **使用索引**：建議在 `user_id` 和 `status` 上建立索引

**建議的優化措施：**
1. **限制查詢數量**：可以添加 `LIMIT` 子句，只分析最近 N 個作品
2. **快取機制**：可以將分析結果快取，避免重複計算
3. **非同步處理**：對於大量作品，可以考慮使用背景任務進行分析

### Q12: 雷達圖數據的更新頻率是什麼？如何確保數據的即時性？

**答案：**

**目前設計：**
- 每次請求都會重新計算，沒有快取機制
- 數據是即時計算的，確保最新

**優點：**
- 數據始終是最新的
- 不需要管理快取失效

**缺點：**
- 如果作品很多，每次請求都需要重新計算，可能較慢

**改進建議：**
- 可以考慮在作品更新時觸發重新計算，並將結果存入快取
- 使用 Redis 或 Memcached 進行快取
- 設置快取過期時間（例如 1 小時）

## 七、總結

### 核心計算邏輯總結

1. **技能分數 = 作品數量權重(40%) + 互動分數權重(30%) + 完整度權重(30%)**
2. **互動分數 = min(100, 瀏覽數×0.1 + 讚數×2 + 評論數×3)**
3. **完整度分數 = 標題(10) + 描述(20) + 內容(20) + 標籤(15) + 封面(15) + 分類(10) + 發布(10)**
4. **技能匹配 = 標籤匹配(權重2) + 文字匹配(權重1)**
5. **最終分數限制在 0-100 範圍內**

### 設計理念

- **多維度評估**：結合數量、互動、完整度三個維度
- **相對公平**：使用相對比例而非絕對數量
- **彈性擴展**：技能類別易於新增和修改
- **容錯處理**：對缺失數據有良好的處理機制

### Q16: 為什麼選擇 40%、30%、30% 這個權重分配？有做過實驗驗證嗎？

**答案：**
這是基於經驗和邏輯推理的設計：
- **40% 給作品數量**：反映學生在該領域的投入和經驗累積
- **30% 給互動分數**：反映作品的受歡迎程度和實用性

**可以調整的方向：**
- 如果更重視作品品質，可以提高完整度權重

### Q35: 為什麼使用 ENUM 類型？有什麼優缺點？

**答案：**

**ENUM 使用範例：**
```1104:1104:database/eportfolio2.sql
  `status` enum('draft','published','review','archived') DEFAULT 'draft',
```

```992:992:database/eportfolio2.sql
  `type` enum('like','comment','view','system','enterprise') NOT NULL,
```

**優點：**
1. **資料完整性**：限制只能輸入預定義的值，防止無效資料
2. **儲存效率**：ENUM 在資料庫中只儲存索引值（1, 2, 3...），比 VARCHAR 節省空間
3. **查詢效率**：比較操作比字串比較快
4. **可讀性**：在資料庫中直接顯示有意義的值

**缺點：**
1. **擴展性差**：新增選項需要修改表結構（ALTER TABLE）
2. **遷移困難**：不同資料庫的 ENUM 實作可能不同
3. **排序問題**：ENUM 按索引值排序，而非字母順序

**替代方案：**
- 使用 **VARCHAR + CHECK 約束**：更靈活，但需要應用層驗證
- 使用 **參考表（Reference Table）**：更規範化，但需要 JOIN 查詢

**本專題的選擇：**
- 對於狀態、類型等固定選項，使用 ENUM 是合理的
- 如果未來需要頻繁新增選項，可以考慮改為參考表

### Q36: 資料庫的觸發器（Trigger）是如何使用的？

**答案：**

```244:261:database/eportfolio2.sql

CREATE TRIGGER `update_portfolio_comment_count_delete` AFTER DELETE ON `comments` FOR EACH ROW BEGIN

        updated_at = CURRENT_TIMESTAMP
```

**觸發器功能：**

- **AFTER DELETE**：評論刪除後觸發

- **缺點**：隱藏邏輯，除錯較困難；可能影響效能

**注意事項：**
- 目前程式碼中同時使用觸發器和手動更新，可能導致重複計算
- 建議統一使用一種方式，避免資料不一致
